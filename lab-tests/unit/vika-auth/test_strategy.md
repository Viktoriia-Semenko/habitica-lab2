# Стратегія генерації Unit-тестів (AI Prompting Strategy)

## 1. Фреймворк та синтаксис
- **Тестовий фреймворк:** Mocha + Chai + Sinon (перевірено за `package.json`; Jest у проєкті немає).
- **Матчери:** тільки Chai (`expect(x).to.equal(...)`, `.to.be.a(...)`, `.to.throw(...)`, `.to.be.calledOnce`, `.to.be.calledWithExactly(...)`). НЕ використовувати Jest-матчери (`toBe`, `toEqual`, `jest.fn()`).
- **Модульна система:** ES6 `import`/`export`, ЯК У САМОМУ ФАЙЛІ, що тестується. Запускаємо ізольовано через `npx mocha --require @babel/register`.
- **Імпорти:** `describe` та `it` доступні глобально через Mocha. Бібліотеки `sinon` та `expect` (з `chai`) імпортувати безпосередньо у файлі тесту, якщо потрібно. Жодних підключень важких системних глобальних конфігів.

## 2. Ізоляція та мокування
- Жодних звернень до реальної бази даних або конфігів (`nconf`).
- **КАТЕГОРИЧНО ЗАБОРОНЕНО** використовувати проєктні хелпери типу `generateReq` / `generateRes` (з `test/helpers/api-unit.helper.js`) або глобальні хелпери `test/helpers/globals.helper.js`. Вони тягнуть за собою ініціалізацію Mongoose (MongoDB), що ламає ізоляцію та призводить до `Timeout Error` при локальному запуску.
- Замість цього об'єкти Express (`req`, `res`) повинні мокатися **тільки вручну** та локально у `beforeEach`.
- **Правило для `res`:** `res = { respond: sinon.stub(), redirect: sinon.stub(), t: sinon.stub().returns('Translation') };`
- **Правило для `req`:** передавати тільки мінімально необхідні поля (наприклад, `url`, `headers`).

## 3. Структура тестів (фікстури)
- Кожна експортована функція тестується в окремому блоці `describe`.
- Мінімум 3 сфокусовані тести (`it`) на кожну функцію.
- Обов'язково покривати "happy path" та edge cases: `undefined`/відсутні аргументи, заблокований/неповний користувач, чутливість до регістру. Окремо покривати гілки коду, що впливають на безпеку (наприклад, редиректи з токеном в URL), навіть якщо вони не є "головним" шляхом виконання.

## 4. Запобігання галюцинаціям
- КАТЕГОРИЧНО заборонено вигадувати або припускати назви функцій, експортів чи полів об'єктів, яких немає у наданому вихідному коді.
- Генерація тестів можлива ТІЛЬКИ якщо в промпті надано точний вихідний код функції, що тестується.
- Не припускати наявність методів на об'єктах `req`/`res`, окрім тих, що явно видно в коді.
