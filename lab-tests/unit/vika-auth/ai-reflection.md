## Рефлексія: AI-агент та unit-тести для `website/server/libs/auth/utils.js`

- **Модуль:** Auth & User - авторизація, профілі, здоров'я
- **Файл під тестами:** `website/server/libs/auth/utils.js` (експортовані функції: `generateUsername`, `loginRes`, `isRestrictedEmailDomain`)

## Переваги побаченого

1. Швидкість: за декілька хвилин з'явився структурований
   каркас тестів де не було жодного - це реально скорочує покриття нового модуля
2. Контекстність: агент самостійно знайшов і використав наявні тестові хелпери проєкту (generateReq, generateRes з test/helpers/api-unit.helper.js), що імітує поведінку реального розробника (хоча пізніше це виявилося проблемою для ізоляції).
3. Покрив усі три експортовані функції хоча б одним щасливим сценарієм —
   з точки зору формального function coverage це виглядає як 100%
4. Код тестів короткий, читабельний, без зайвої абстракції

## Недоліки побаченого

1. Тест-пустушка - (false sense of security)
   ```js
   expect(() => loginRes(user, req, res)).to.throw;
   ```
   Забутий виклик `()` після `.throw`. у Chai `throw`  - без
   дужок він просто звертається до властивості функції та нічого не
   перевіряє. Тест буде зеленим незалежно від того, кидає код виняток чи
   ні 
2. Не протестовано саму причину існування рядка коду
   `isRestrictedEmailDomain` явно робить `.toLowerCase()`, але тест не
   перевіряє чутливість до регістру (`Test@HABITICA.COM`) - тобто немає
   тесту саме на ту логіку, заради якої цей рядок і був написаний
3. Під час першого запуску виникла помилка Cannot use import statement outside a module. Проблема була не в самому використанні import, оскільки Habitica також використовує ES6 import/export, а в тому, що тест запускався без project Babel configuration. AI не врахував необхідний test runner setup
4. Порушення ізоляції Unit-тестів: агент використав системні хелпери, які під капотом ініціалізують з'єднання з базою даних Mongoose (MongoDB). Це призвело до того, що при локальному запуску тести падали з Timeout Error. AI не зрозумів, що для чистих, швидких unit-тестів складні об'єкти (req, res) безпечніше мокати локально вручну (наприклад, через sinon.stub()), щоб не піднімати всю інфраструктуру бекенду
